GitHub Issue を作成してください。

## 手順

### 1. 内容を把握する

- 引数がある場合はそのまま使う
- 引数がない場合は「何の Issue を作りますか？」と聞く

### 2. 設計方針を批判的に検討する（メインコンテキストで実行）

グローバル CLAUDE.md のルールに従い、実装前に批判的検討を行う。

- 取り組む内容に対して **2〜3 の実装アプローチ**を提示する
- 各案のトレードオフ（工数・可読性・拡張性・既存設計との整合性）を説明する
- ユーザーの意見を鵜呑みにせず、懸念点や代替案を積極的に伝える
- `docs/architecture.md` を参照して関連する過去のアーキテクチャ判断（ADR）と整合させる
- `docs/decisions.md` を参照して実装フェーズでの過去の個別判断とも整合させる

**ユーザーの合意が得られてから Step 3 に進む。合意前に planner には委譲しない。**

UI を含む場合（新規ページ・コンポーネント追加・既存画面の大幅な刷新）は、合意後にデザイン方針を決めてから Step 3 に進む（`/frontend-design` 相当のスキルが導入済みであればそれを実行、未導入ならこの場でユーザーと方針を詰める）。

### 3. planner サブエージェントに委譲する

合意した方針と、引数（Issue 番号または説明文）を planner に渡す。

- 作成した Issue の URL をユーザーに報告する

## 注意事項

- 実装は Issue 作成後に行う。このコマンドでは実装しない
- 会話中に「〜したい」「〜が必要」という話題が出たら積極的にこのコマンドを提案する
