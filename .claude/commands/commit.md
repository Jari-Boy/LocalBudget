現在の変更を確認し、lint を通してからコミットを作成してください。

## 手順

1. **事前チェック**

   ```bash
   git branch --show-current
   ```

   - **現在のブランチが `main` の場合は以下を実行する（コミットは中断）**：
     1. `git branch` でローカルブランチ一覧を確認する
     2. `main` 以外のブランチが存在する場合 → 一覧をユーザーに見せ「既存のブランチに切り替えますか？それとも新しくブランチを作成しますか？」と確認する
     3. `main` 以外のブランチが存在しない場合 → 「main への直接コミットは禁止です。どのようなブランチ名を作成しますか？」と聞き、`git checkout -b <名前>` で作成する
     4. ブランチが確定したらコミット手順を続ける
   - 変更ファイルの一覧（`git status`）に `.env`・`*_key*`・`*secret*`・`*credential*` などの機密ファイルが含まれていないか確認する。含まれている場合は理由を聞いてからでないとコミットしない

2. **Lint チェック（必須）**
   - `linter` サブエージェントに ESLint・tsc チェックを依頼する
   - FAIL の場合はコミットを中断してユーザーに問題一覧を報告する
   - **lint 違反が残っている状態でコミットしない**

3. **コミット作成（`committer` サブエージェントに委譲）**
   - ブランチが確定し lint が PASS したら、`committer` サブエージェントに変更確認〜コミット実行を依頼する
   - `committer` が機密ファイル検出により中断を報告した場合 → 該当ファイルをユーザーに見せ、含める理由を確認してから再度依頼するか判断する
   - `committer` が成功を報告した場合 → コミットハッシュとメッセージをユーザーに報告する

## 注意事項

- **main ブランチへの直接コミット禁止**。ブランチを確認してから進む
- `git add -A` は使用禁止。ファイルを個別に指定すること
- lint 違反が残ったままコミットしない
- `.env` や機密情報を含むファイルは絶対にコミットしない
- コミットは新規作成のみ。`--amend` は使わない（ユーザーから明示的に指示された場合を除く）
