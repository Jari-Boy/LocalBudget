## 1. 期間確定と締め

### 1.1 締め(ロック)は設けない

- 過去期間の編集・削除は常に可能とする。
- 誤操作対策として、集計済み期間を編集する際に確認ダイアログを表示する(例:「◯◯月は集計済みです。変更しますか?」)。
- 外部提出が必要な場合は、その時点のFSを **PDF/CSVでエクスポート** し、スナップショット出力で対応する。

### 1.2 資産の照合可否

`is_reconcilable`フラグは、CSV取込・突合機能の出し分けに用いる。

| 資産の種別 | 残高の根拠 | is_reconcilable | 入力手段 |
|---|---|---|---|
| 照合可能資産(銀行口座・電子マネー) | 外部明細という客観的な正が存在 | `true` | CSV明細の取込・突合([reconciliation.md](./reconciliation.md)参照) |
| 照合不能資産(現金) | 仕訳の積み上げのみ | `false` | 実残(残高を数えて過不足調整) |

**残高調整(実残調整・原因不明差異の確定)**

`is_reconcilable = false`の資産(現金)は、ユーザーが数えた実際の残高と帳簿残高が食い違うことがある。`is_reconcilable = true`の資産でも、[reconciliation.md 1.5 残高照合](./reconciliation.md#15-残高照合)を経てなお原因不明の差異が残ることがある([reconciliation.md 1.6](./reconciliation.md#16-原因不明差異への残高調整)参照)。いずれも、システム管理科目「費用・残高調整」(`category = 'expense'`, `is_system_managed = true`、[accounts.md 1.2](./accounts.md#12-区分5要素)参照)を相手科目とする調整仕訳で解消する。この調整仕訳の`source_type`は`balance_adjustment`とする([journal.md 1.7 作成経路(source_type)](./journal.md#17-作成経路source_type)参照)。トリガー(実残の手入力かCSV残高との比較か)が異なるだけで「帳簿と外部の正との差異を吸収する」という会計処理上の構造は同じであるため、科目を共通化する。専用のBS科目(資産・負債)を新設するのではなく既存のexpense区分の1科目とし、`side`で過不足の向きを表現することで、[2.1 生成方式](#21-生成方式)の残高計算の一般式(expenseは`debit - credit`)をそのまま適用できるようにする。

```
例: 帳簿上の現金残高は10,000円だが、実際に数えたら9,200円だった(800円不足)

(借) 費用・残高調整     800
(貸) 資産・現金                 800

例: 逆に実際の残高の方が多かった(300円多かった)場合は貸借を反転させる

(借) 資産・現金           300
(貸) 費用・残高調整           300   ← 費用のマイナス計上(貸方超過)としてPLに反映される
```

## 2. 財務諸表(FS)

### 2.1 生成方式

- PL(損益計算書) = 指定期間内の収益科目・費用科目に属する仕訳明細の合計。毎回計算する。
- BS(貸借対照表) = ある基準日までの資産科目・負債科目・純資産科目の残高。毎回計算する。
- 残高スナップショットは保持しない。

**複式簿記の恒等式とBSの純資産部**

決算振替仕訳(収益・費用を繰越利益へ振り替える仕訳)は行わない設計であるため、BSを「資産・負債・純資産の3区分の残高だけ」で計算すると、収益・費用の分だけ貸借が一致しなくなる。複式簿記の恒等式

```
資産 = 負債 + 純資産 + (収益 - 費用)
```

が任意の基準日で成立するように、BSの純資産部は以下の式で計算する。

```
BS純資産部(基準日) =
    Σ(純資産科目の貸方残高、基準日まで)
  + Σ(収益科目の貸方残高、基準日まで)
  - Σ(費用科目の借方残高、基準日まで)
```

「収益科目の貸方残高 − 費用科目の借方残高」の部分は、会計期間で区切らない通算の当期純利益に相当する。表示上は、純資産を「元手(初期残高等のsystem-managed科目)」と「損益の累積」に分けて2行で見せるか、合算して1行で見せるかはUI側の裁量とし、本設計書では計算式の正しさのみを担保する。

**残高計算の一般式**

科目単位の残高は、区分ごとに「増加側」が異なるため、以下のように正規化して計算する。

| 区分 | 増加側 | 残高の式 |
|---|---|---|
| asset / expense | 借方 | `debit - credit` |
| liability / equity / revenue | 貸方 | `credit - debit` |

### 2.2 表示UI

ユーザーは期間(または基準日)を選ぶだけでFSを生成できる。任意区間(「先週」「今日から給料日まで」等)の切り替えに対応する。

| 対象 | 指定方法 | 備考 |
|---|---|---|
| PL | 開始日・終了日(区間) | 月次・年次はプリセット提供 |
| BS | 単一の基準日(時点) | 「◯月◯日時点」の残高、入力コスト1つ少ない |
| プロジェクト別 | プロジェクトを選択(+任意で期間) | 期間を指定しなければ全期間を集計対象とする。[projects.md 1.4](./projects.md#14-集計への影響)参照 |
| メンバー別 | 世帯メンバーを選択(+任意で期間・プロジェクト) | [household-members.md 1.4](./household-members.md#14-集計への影響)参照 |
| 取引先別 | 取引先を選択(+任意で期間) | 期間を指定しなければ全期間を集計対象とする。[counterparties.md 1.7](./counterparties.md#17-集計への影響)参照 |
| 比較 | 前期・前年同期など | 任意機能 |
