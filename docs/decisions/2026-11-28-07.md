## 2026-11-28: 意思決定ログを1決定=1ファイルに分け、置き換え関係をfrontmatterで持たせる(計画Issue #310)

**背景**: 意思決定ログは1ファイルの追記専用ログ(`decisions.md`、約720KB・220件)だった。現行の判断を引くには、後の決定で置き換えられていないかを確かめるために時系列を全部読む必要があった。OKFの「1ファイル1概念」にも合わなかった。

**決定**:
- 見出し単位(220件)で `docs/decisions/` に1決定=1ファイルへ分け、元の `decisions.md` は削除した。
- id は `YYYY-MM-DD-NN`(日付-その日の連番)とし、ファイル名と一致させる。
- 置き換え関係は frontmatter の `supersedes`・`partially_supersedes` と、対応する `superseded_by`・`partially_superseded_by` で持たせた(全面4件・一部26件)。全面的に置き換えられた決定は `status: deprecated` にして、`index.md` の「置き換え済みの決定」へ移した。
- 本文は書き換えず、分割で壊れる相対リンク2件だけを補正した。
- 置き換え関係は、本文に明示されたものに限った。本文に書かれていない暗黙の置き換えは未対応(別途拾う)。
- `patterns.md`・`knowledge.md` は対象外とし、従来どおり追記専用の履歴ログのままにする。

**影響**:
- 現行の決定は `docs/decisions/index.md` の「現行の決定」だけを見ればよい。置き換え済みかどうかは frontmatter で機械的に分かる。
- `npm run docs:check` に、置き換え関係の相互参照、index への掲載、相対リンクの実在、本文中の決定参照の実在の検査を足した。
- 参照元(各文書・agents・コード内コメント)は新しい場所へ張り替えた。新しい決定は、1決定=1ファイルで追加し、置き換えるときは旧決定の本文を書き換えず新しい決定側に関係を書く。
