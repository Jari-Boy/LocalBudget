## 2026-11-23: 割勘画面の「過去の割勘」を最上位の「履歴」タブへ移し、候補と履歴を150件ずつの表示にする(計画Issue #268)

**背景**: 割勘画面は、割勘タブの最下部に「過去の割勘」があり、仕訳が増えると候補の表の下に埋もれて見つけにくかった。あわせて、候補の表も履歴も全行を描画していて、仕訳が増えると描画が重かった。仕訳一覧(計画Issue #253)には150件ずつの分割表示が既にある。
**決定**:
1. **履歴は割勘タブの副タブにせず、画面最上位のタブ「履歴」にする**。タブの並びは「割勘・精算・履歴」で、履歴は精算の右どなり。タブ名は「履歴」だけで件数は付けない。中身は割勘の履歴だけ(精算バッチの履歴は精算タブにあり、名前は紛らわしいが、割勘タブの中にさらにタブを重ねる案は操作の階層が深くなるため採らなかった。ユーザー判断)。最初に副タブ案でモックを作り、承認前に最上位タブへ変えた。
2. **絞り込みボタンはタブの行の右端のまま(計画Issue #266の位置は変えない)、割勘タブのときだけ出す**。履歴は左寄せに置くので、絞り込みボタンの有無で履歴タブの位置は動かない。
3. **履歴タブは取り消しの確認と詳細ダイアログの状態を自分で持つ(`SplitHistoryTab`)**。割勘タブの候補の摘要から開く詳細ダイアログは割勘タブが持つ。
4. **件数の上限は150件ずつ「さらにN件表示」**。候補と履歴の両方。仕訳一覧(#253)の共通化できる部分(件数を決める関数と末尾の部品)を`common/list-paging/`(`listPaging.ts`・`ListLoadMore`)に切り出し、仕訳一覧もそれを使う(挙動は変えない)。仕訳一覧の表示方式別の定数`JOURNAL_LIST_PAGE_SIZE`は流用せず、割勘画面の定数`SPLIT_LIST_PAGE_SIZE`を別に持つ。ページ番号式・仮想スクロールは採らない。
5. **チェック済みの仕訳が150件の外にあるときは、その仕訳(複数なら表示順でいちばん後ろのもの)が見えるまで表示を広げる**。合計に含まれる仕訳が見えなくなるのを防ぐため。絞り込みで隠れた仕訳は、従来どおりチェック済みなら合計に含め、表示は広げない。絞り込み条件を変えるか、履歴の未精算/精算済みを切り替えると、増やした件数は先頭の150件に戻す。
6. **今回の絞りは描画だけが対象**。全仕訳の読み込みと、候補・履歴の導出は従来どおり全件のまま。実装前の計測は行わなかった(ユーザー判断)。読み込み・導出が支配的で体感が変わらない場合は別の計画Issueで扱う。
7. **URL**: 最初に開くタブは`?tab=history`でも指定できる。旧URL`/journal/splitting/history`は`?tab=history`へリダイレクトする(計画Issue #153の旧URLリダイレクトの行き先を、履歴タブに変えた)。
**影響**: `SplitSettleScreen`の`initialTab`の型に`'history'`が増えた。`SplitTab`から履歴の状態と表を外した。行単位の割勘(計画Issue #271)の実装時には、割勘タブの候補の単位(仕訳→行)と150件の数え方が変わりうる。
